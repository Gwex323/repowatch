# P5 记忆生命周期与检索

核验对象：2026-11-09 的 P5 实现与受控验收。记忆来源事实、索引和模型上下文分别保存；阶段放行及最终回归结果以 [NOW](../context/NOW.md) 为准。

## 事实、提炼与预算

`repository_memories` 保留不可变的初始正文、仓库、来源任务／运行／修复会话、代码版本和产物摘要引用。`memory_versions` 追加正文版本，`memory_heads` 保存当前修订、验证／反馈状态、禁用和删除标记。初始记录及后续修改与 `memory_index_events` 在同一业务事务提交。

Worker 将已验证且独审通过的 `distillation_intents` 转为串行维护任务，消费后标记 `consumed`。维护任务没有新预算，使用原来源的 `budget_owner_task_id`；全局／仓库暂停、撤销预算及单执行位约束仍适用。工具仅有 `read_evidence`，不能操作源码或 Runner。提炼失败保留意图；模型故障和预算不足仍进入已有处理／恢复流程。重新调度会先核对已有来源记录，不以新 ID 绕过人工删除。

来源任务被用户排除或取消时，不新建或领取维护任务；已领取的任务在后续模型／工具请求和记忆提交前再次检查。等待来源恢复的任务复用原身份；重新启用来源不会恢复已经撤销的预算，也不会撤销维护任务自身的排除或取消。

人工内容为 `manual_unverified`；失败尝试单独保存，不能当作成功方案。修复通过不等于根因已证实，未证实内容写入限制。PR 接受、关闭和合并状态独立读取。

失败经验是修复失败路径的附加记录。产物冲突、验证或持久化约束冲突会跳过本次记录并留下 `failure_memory_skipped` 诊断，原修复进展检测和失败处理继续；真实业务存储故障仍停止执行。

自动提炼默认保留在仓库范围。跨仓共享须在界面中改写为去敏通用正文并明确确认；不能确认时不共享。程序拒绝明显凭据、代码块、原始绝对路径、URL 和长摘要标识。共享正文与本仓正文分开保存；检索其他仓库时只返回共享正文、记忆 ID 和修订，不返回原始产物、完整历史或源码引用。人工确认不使语义编辑自动继承验证标签。

## 反馈、人工纠正与删除

来源任务反馈修订变化，在同一事务中将相关可用经验改为 `feedback_pending` 并登记索引事件。尚未提炼的旧证据通过来源反馈水位在落库时成为 `pending_review`。Worker 仅在读取新反馈与原证据后判断：无关／格式意见可恢复仍匹配的内容版本；真实反证保留待返修复核，返修成功产生有新来源证据的记录。共享正文同时受到来源状态和内容版本限制。

GitHub 反馈送入模型前去除传输 URL、账户外观及嵌套仓库统计元数据，保留账户／仓库身份、base/head SHA、正文、评审、文件 diff 与 CI 事实；自定义来源反馈不按 GitHub 字段裁剪。工具返回解析后的 `payload` 及原始正文的 `payload_sha256`，原始反馈仍保存在业务库，预算与单步输入上限不变；实际证据仍过大时继续拒绝，不截断后声称完整。

成功与失败经验落库都核对来源反馈水位。失败经验保留原验证类型，即使经过多轮反馈复核，无关意见也只恢复为 `failure`。

复核提交必须匹配记忆修订、来源摘要和最新反馈修订。期间人工编辑、禁用、删除或新增反馈，迟到判断不生效；普通竞争正常结束，不为恢复旧记忆新建身份。人工语义编辑产生新版本并清除旧验证标签。

删除是事实源中的持久停用标记，立即影响未来检索和注入；派生索引可随后重建清理。来源事实、正文历史、原任务证据及已发送的请求是独立审计留存对象，不宣称删除记忆会撤回历史请求或擦除任务证据。

## 可重建索引与降级

`memory-index.sqlite3` 是派生库，独立于业务库和 LangGraph 检查点。FTS5 使用同一版本规则处理查询与正文：拆分下划线／驼峰标识符，保留原始标识符，并用中文双字片段支持短词。业务库待索引事件和索引水位不同步时回查当前事实，遗漏的新记录可走范围／关键词回源；旧修订、禁用、删除、反馈待判断及未验证内容不进入注入。

事实提交后的派生索引重建失败会登记 `memory_index_deferred`，保留待索引事件，事实维护任务仍可完成；可从管理入口重建。业务存储故障仍须停止并对账。状态查询和检索以只读连接访问派生库，不创建索引表；初始化仅在显式重建时进行。

语义配置默认关闭；先前真实语料复评未选出通过门槛的默认模型，见[嵌入复评](embedding-evaluation.md#真实-issuepr-复评与资产锁定)。已接入锁定模型的本地 CPU 编码适配、L2 归一化与 sqlite-vec 余弦距离；候选模型须明确选择并准备匹配资产，不隐式下载。配置、维度、资产摘要或编码规则变化，旧向量不能继续混用；完整重建事务成功后才发布新索引元数据。当前对过滤后的向量进行精确距离排序，尚无大规模近似索引性能承诺。

关键词与向量各自先限定本仓／可共享范围，再用倒数排名融合，不直接相加不同量纲分数；返回前再核对事实源修订、反馈状态和源产物可用性。条数与上下文长度有上限。语义不可用明确返回 `keyword`，索引缺失／损坏或编码规则不匹配时返回 `range` 及原因。损坏派生库可显式重建，旧文件隔离保留；不会把锁竞争或磁盘故障误作损坏处理，更不会重建业务库来掩盖事实丢失。

编码依赖：`uv sync --project backend --locked --group embedding --group dev`。锁定资产清单随 wheel 分发；模型实体需预先准备在受管数据目录下 `embedding-assets/models--<来源组织>--<模型>/snapshots/<revision>/`，文件清单和 SHA-256 须与 [资产锁](../../experiments/embedding-assets.lock.json) 一致。P6 仍负责完整安装分发，不把实验缓存当作默认产品资产。

## 模型调用与检查点

独立记忆块绑定 ID／修订，记录于 `memory_injections`。每个新请求及供应商重试前均重新核对依赖；结果进入业务验证前再次核对。依赖改变时，丢弃该阶段旧会话、摘要及压缩缓存，使用当前任务输入和有效证据建立新的图线程，而不是继续发送旧历史。恢复已完成阶段也会先重新选择当前依赖，旧检查点不能绕过这一步。

同步子任务的摘要依赖会继承到父阶段，父级新请求、缓存结果和检查点复用也核验子树的记忆修订。即使父任务没有直接检索到该经验，也不能将子任务旧摘要重新发送。失效时父／子阶段使用新命名空间重建，不沿用旧摘要。

上下文连续变化最多重建三次，仍受来源累计预算和阶段上限约束，不清零进展检测历史。`memory_request_audits` 记录请求前依赖检查；实际调用和发送情况以供应商调用账本及运行证据为准。审查和提炼不直接检索注入修复经验，保持独立只读范围。配置 `memory_enabled=false` 可显式禁用新阶段检索；已有依赖仍需清理旧上下文。
