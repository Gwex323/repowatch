## ADDED Requirements

### Requirement: 仓库进度可直接查看

控制台 SHALL 默认按仓库显示分析、待办与交付，提供概览、分析、问题与修复和配置；宽屏分栏，窄屏单列并维持可读字号。

#### Scenario: 当前目标变化
- **WHEN** 当前目标与最近可核验的已完成扫描属于不同版本
- **THEN** 分开显示两者，旧版本保留证据且不表示当前版本就绪

### Requirement: 扫描发现能够追踪至修复

控制台 SHALL 在扫描发现提供可核对的依据，并在确认 Issue 身份后提供该编号的直达入口；扫描版本、代码区域和跟进进度筛选可按需展开。

#### Scenario: 查重结果不明确
- **WHEN** 系统完成查询但尚无法确认同一问题
- **THEN** 显示当前已核实的查重结论，存在具体相似项时指出编号并提供依据；判断提交后以当前查询和修订重新核验

#### Scenario: 修复通过但仍等待 CI
- **WHEN** 有已核验的修复证据且受管 PR 等待远端检查
- **THEN** 界面分别展示验证结论和 PR 状态，可查看实际证据，等待 CI 不产生人工待办

### Requirement: 操作按作用范围归位

控制台 SHALL 为仓库级配置和经验提供仓库入口，为账号、模型、诊断、维护和索引提供全局入口。全局待办只显示当前需要操作者处理的事项，并允许从相关仓库定位。

#### Scenario: 按建议一键处理阻塞
- **WHEN** 操作者按具体原因和建议处理后点击「已解决，重新检查」
- **THEN** 无需填写说明或重试计划，系统记录核验及有限重试依据，全部恢复条件满足时一并恢复队列；核验失败更新原因并保留阻塞，刷新本身不执行任务

#### Scenario: 原 Issue 包含多个独立目标
- **WHEN** 分诊要求收敛或拆分多个独立目标
- **THEN** 提供可核对的范围及已有绑定，按既有契约明确确认后才允许逐项查重和独立交付
