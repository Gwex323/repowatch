## Why

旧控制台按任务类型和维护功能组织；仓库扫描、发现、Issue、验证证据和 PR 分散，用户需要自己拼出一次修复的进度。2026-11-12 已确认采用原型「进度一览」和以仓库为中心的主流程。

## What Changes

- 默认打开仓库进度一览，仓库内按「概览｜分析｜问题与修复｜配置」组织。
- 扫描发现显示可读的进度和下一步；已确认的关联显示可点击的 Issue 编号，查重存疑时展示系统发现和对比依据。
- 证据、PR、待办和设置各有可追溯入口，延续现有预算、恢复、验收和远端发布门禁。
- 分两关验收：仓库主链路与待办；其余功能覆盖与需要补齐的后端流程。第二关包含多目标 Issue 的收敛／拆分。

## Capabilities

### New Capabilities

- `repository-workbench`：仓库一览、扫描证据、问题与修复、操作待办及设置入口。

### Modified Capabilities

- 无新增发布授权；多目标 Issue 依既有交付约束完成，验收映射见任务清单。

## Impact

- React 控制台、现有回环查询投影、离线浏览器验收脚本。
- 用户数据库、真实 GitHub 和模型运行不属于本次浏览器验证。
