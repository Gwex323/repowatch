# Proposal

## Why

登记每个仓库都要手填 GitHub 凭据引用。把 GitHub 账号集中管理后，可以绑定一次并在多个仓库复用，同时保留逐仓库的身份、目标和权限检查。

## What Changes

- 系统页支持以用户名和 PAT 绑定多个 GitHub 账号、设为默认、验证、更换令牌及解绑。
- 新仓库预选默认账号；保存后固定所选账号。旧仓库可继续使用已有凭据，或经预检显式改绑。
- 仓库登记使用 GitHub 仓库链接定位上游，重新预检时从已保存的仓库身份填回链接。
- 新登记默认在发布 PR 时自动选择贡献路径。登记和扫描不要求上游推送权限或现成 Fork。
- 仓库一键登记，已有仓库的准入与扫描策略按需编辑。
- 供应商页面使用表单新增，移除 JSON 整批新增入口。新增／编辑供应商时可拉取模型列表；角色绑定从供应商已保存的配置中选择。
- 令牌由 Windows 凭据库保管；绑定、默认选择及仓库授权保持独立。

## Capabilities

### New Capabilities

- `github-account-binding`：管理 GitHub 账号及默认选择，并将已验证账号用于仓库登记。
- `provider-model-selection`：在供应商表单拉取模型，在角色表单选择已配置模型。

### Modified Capabilities

当前主规格库为空。本变更以新能力补充现有 Harness 变更中的仓库预检和本地控制要求。

## Impact

影响系统与仓库界面、本地控制 API、凭据解析、仓库登记及业务库迁移。不引入 OAuth 或扩大仓库写入授权。
